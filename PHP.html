A server-side scripting language purpose-built for the web — powering CMS platforms, e-commerce backends, and APIs across the internet.

1 Introduction

PHP is a server-side scripting language purpose-built for the web. Code runs on the server and outputs HTML, JSON, or other content back to the browser — making it the engine behind a huge share of the web, including WordPress, and platforms like Facebook's early stack.

PHP is easy to embed directly inside HTML, has a low barrier to entry, and comes with built-in support for common web tasks: sessions, forms, file uploads, and database access.

    • 2 History

    PHP was created by Rasmus Lerdorf in 1994, originally as a set of Common Gateway Interface (CGI) scripts. The name stood for "Personal Home Page Tools" before becoming the recursive "PHP: Hypertext Preprocessor."

    12 Classes

    class Animal {
    public function __construct(protected string $name) {}
    public function speak(): string {
        return "{$this->name} makes a sound";
    }
}
class Dog extends Animal {         // inheritance
    public function speak(): string {
        return "{$this->name} barks";  // override
    }
}
$d = new Dog("Rex");
$d->speak(); // "Rex barks"
  • __construct is the constructor.
  • Constructor property promotion (protected string $name) declares and assigns in one step.
  • extends sets up inheritance.

    19 Memory Management

    PHP uses automatic reference counting plus a cycle collector, similar in spirit to Python. Memory for a request is typically freed entirely at the end of that request's lifecycle under PHP-FPM.

    20 Performance

    • Enable OPcache to avoid re-parsing scripts on every request.
    • Use the JIT compiler (PHP 8+) for CPU-heavy workloads.
    • Avoid N+1 database queries — eager-load relationships.

    21 Best Practices

    • Use Composer for dependency management.
    • Follow PSR coding standards (PSR-12).
    • Separate concerns — avoid mixing heavy logic directly into HTML templates.
    • Use type declarations for parameters and return types.

    22 Security

    • Use prepared statements (PDO) to prevent SQL injection.
    • Escape output with htmlspecialchars() to prevent XSS.
    • Never trust $_GET/$_POST without validation.
    • Keep PHP and dependencies patched.
    // Bad
$q = "SELECT * FROM users WHERE id=$id";
// Better
$stmt = $pdo->prepare("SELECT * FROM users WHERE id=?");
$stmt->execute([$id]);

    23 Accessibility

    Accessibility comes from the HTML PHP generates, not PHP itself — use semantic markup, labels, and ARIA attributes in your templates.

    24 Code Style

    • Follow PSR-12: 4-space indentation, braces on new lines for classes/functions.
    • camelCase for methods/variables, PascalCase for classes.
    • Use PHP-CS-Fixer or PHP_CodeSniffer to enforce style.

    27 Common Mistakes

    • Mixing PHP and HTML too heavily, making templates hard to maintain.
    • Trusting user input directly in SQL queries or shell commands.
    • Using == instead of ===, causing loose-comparison bugs.
    • Not handling exceptions from external calls (DB, HTTP).

    28 Interview Questions

    Q: Difference between == and ===?
    A: == compares values with type coercion; === compares both value and type.
    Q: What is Composer?
    A: PHP's dependency manager — it installs packages and generates an autoloader for your project.
    Q: What are traits?
    A: Reusable blocks of methods that can be mixed into multiple classes, working around PHP's single-inheritance limit.

    32 FAQ

    Include vs require?
    Both import a file; require fatally errors if the file is missing, include only warns.
    Session vs cookie?
    Sessions store data server-side keyed by a cookie ID; cookies store data directly in the browser.
