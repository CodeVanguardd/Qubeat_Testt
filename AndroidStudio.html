Android Studio

The official Android IDE, built on IntelliJ IDEA — everything you need to build, run, debug, and profile Android apps.

1 Introduction

Android Studio is the official Integrated Development Environment (IDE) for building Android applications, built on JetBrains' IntelliJ IDEA platform.

Type
Integrated Development Environment (IDE), not a language
Runs on
Windows, macOS, Linux
Used for
Building, testing, and debugging Android apps

Every new project starts from a template, is written in Kotlin or Java, designed with the Layout Editor, and run on an emulator or physical device — all inside one IDE.

2 History & Founders

Android Studio is developed by Google, announced at Google I/O in May 2013. It is built on IntelliJ IDEA, the IDE platform created by JetBrains (founded by Sergey Dmitriev, Eugene Belyaev, and Valentin Kipiatkov). Android Studio officially replaced the Eclipse ADT plugin as Google's recommended tool in 2014.

YearMilestone
2013Announced at Google I/O, built on IntelliJ IDEA
2014Officially replaces the Eclipse ADT plugin

PresentContinuous rolling releases synced with the IntelliJ platform

3 Versions

Releases historically carried dessert-themed codenames, then switched to alphabetical letter names tied to IntelliJ platform versions, e.g. Arctic Fox, Bumblebee, Chipmunk, Flamingo, Giraffe, Hedgehog, Iguana, Koala, Ladybug.

4 Project Structure

A typical Android Studio project layout:

app/
├── src/main/java/      // app source code
├── src/main/res/        // layouts, drawables, strings
├── AndroidManifest.xml
└── build.gradle.kts

5 Core Workflow

The core workflow inside Android Studio:

  1. Create a project from a template
  2. Design the UI in the Layout Editor
  3. Write app logic in Kotlin or Java
  4. Run on an emulator or connected device
  5. Debug with Logcat and the built-in debugger

EditorLayout EditorGradleEmulator LogcatProfilerDevice ManagerVersion Control

7 Supported Languages

Android Studio officially supports Kotlin (Google's preferred language since 2019) and Java for app logic, XML for layouts and resources, and C++ via the NDK for native/performance-critical code.

8 Build Variants

Build variants combine build types (debug/release) with product flavors, letting a single project produce multiple app versions (e.g. free vs. paid) from one codebase.

9 Gradle Build System

Android Studio uses Gradle as its build system — build.gradle/build.gradle.kts scripts compile code, package resources, and manage dependencies.

10 Run & Debug Workflow

Run ▶ builds and deploys the app to an emulator or device. Debug 🐞 attaches a debugger with breakpoints, variable inspection, and step-through execution.

11 Built-in Tools

Built-in tools include the Layout Inspector, APK Analyzer, the CPU/Memory/Network Profiler, and Lint code inspections.

12 Project Templates

Project and Activity templates (Empty Activity, Bottom Navigation Activity, and more) scaffold common app structures instantly, saving boilerplate setup.

13 UI Design Tools

The Layout Editor offers drag-and-drop XML UI design, and the Jetpack Compose Preview gives a live preview for declarative UI code.

14 Architecture Support

Android Studio encourages the Jetpack Architecture Components (ViewModel, LiveData, Room, Navigation) for building clean, testable app architecture.

15 Modules

Projects are organized into modules — an app module plus optional library or feature modules — each independently manageable within one project.

16 Libraries & Integrations

Jetpack ComposeFirebaseRetrofitRoomCameraXMaterial Components

17 Emulator & Device Testing

The Android Emulator simulates devices and API levels; the Device Manager provisions virtual devices; real devices connect for testing over ADB.

18 Debugging Tools

Logcat streams system and app logs in real time. Breakpoints and the built-in debugger let you inspect variables and step through code during execution.

19 Profiling Tools

Built-in CPU, Memory, Network, and Energy Profilers help detect memory leaks, UI jank, and battery drain directly inside the IDE.

20 Build Performance

Tools for keeping builds fast: Baseline Profiles, the Macrobenchmark library, and the Build Analyzer for diagnosing slow Gradle builds.

21 Best Practices

  • Keep Gradle and the Android Gradle Plugin updated.
  • Use version catalogs to manage dependencies consistently.
  • Use Apply Changes for faster iteration while developing.

22 App Security

  • Check Google Play Console's pre-launch reports before release.
  • Use Lint's security inspections.
  • Enable R8/ProGuard for code shrinking and obfuscation in release builds.

23 Accessibility

The Accessibility Scanner integration flags missing content descriptions, low contrast, and undersized touch targets directly during development.

24 Editor Intelligence

Android Studio inherits IntelliJ's smart code completion, refactoring tools, and automatic code formatting to keep code consistent as you type.

25 Recommended Architecture

MVVM

The officially recommended architecture pattern, directly supported by Jetpack libraries like ViewModel and LiveData/StateFlow.

27 Common Mistakes

  • Ignoring Gradle sync errors instead of resolving them.
  • Skipping SDK/Emulator updates.
  • Not testing across multiple screen sizes and API levels.

32 FAQ

Is Android Studio required for Android development?
It's Google's official, fully supported IDE; alternatives exist but lack the same first-party tooling and Google backing.

33 Pros and Cons

Pros
  • Official Google support
  • Deep Kotlin and Jetpack integration
  • Powerful debugging and profiling tools
Cons
  • Resource-heavy on lower-end machines
  • Gradle builds can be slow on large projects
