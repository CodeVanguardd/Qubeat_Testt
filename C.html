C

The low-level, procedural language behind operating systems, compilers, and embedded devices — direct control over memory and hardware.

1 Introduction

C is a low-level, procedural programming language that gives direct control over memory and hardware. Created in the early 1970s, it became the foundation for countless operating systems, compilers, and embedded systems — and directly influenced C++, C#, Java, and JavaScript's syntax.

C has no garbage collector, no built-in objects, and minimal runtime — everything is explicit, which makes it fast but demands discipline from the programmer.

    4 File Structure

    C source files use .c, headers use .h. Compilation produces an executable binary.

    // main.c
#include <stdio.h>      // 1. includes
#define MAX 100       // 2. macros
int add(int a, int b); // 3. declarations
int main() { return 0; }  // 4. entry point

    12 Classes

    C has no classes — it's procedural. Structures group related data instead:

    typedef struct {
  char name[50];
  int age;
} Person;
Person p = {"Ana", 30};

    13 Objects

    No native objects — behavior is achieved through structs plus function pointers:

    typedef struct {
  int x, y;
  void (*print)(void*);
} Point;

    17 APIs

    C interacts with the OS through system calls, often wrapped by the standard library.

    FILE *f = fopen("data.txt", "r");
fclose(f);

    18 Error Handling

    C has no exceptions — errors are typically signaled through return codes and errno.

    FILE *f = fopen("x.txt", "r");
if (f == NULL) { perror("fopen failed"); }

    19 Memory Management

    C requires manual memory management with malloc/free. Forgetting to free causes memory leaks; using freed memory causes undefined behavior.

    int *arr = malloc(10 * sizeof(int));
free(arr); // must free manually

    20 Performance

    • C compiles directly to machine code — minimal runtime overhead.
    • Avoid unnecessary heap allocation in hot loops; prefer stack arrays.

    21 Best Practices

    • Always check malloc's return value for NULL.
    • Free every allocation, exactly once.
    • Use const for read-only pointers/parameters.

    22 Security

    • Buffer overflows: always bound-check array/string operations.
    • Avoid unsafe functions like gets(); use fgets() instead.

    28 Interview Questions

    Q: Difference between malloc and calloc?
    A: malloc allocates uninitialized memory; calloc allocates and zero-initializes it.
    Q: What is a segmentation fault?
    A: A crash caused by accessing memory the program doesn't have permission to access.
