Kotlin

A modern, concise, null-safe language for the JVM, officially preferred by Google for Android development.

1 Introduction

Kotlin is a modern, statically typed language that runs on the JVM (and compiles to JS/Native), officially supported by Google for Android development.

Type
Compiled, statically typed, Java-interoperable
Runs on
JVM, Android, browsers (Kotlin/JS), native binaries
Used for
Android apps, backend services, multiplatform apps
fun main() { println("Hello, Kotlin!") }

2 History

Created by JetBrains, first announced in 2011, with Kotlin 1.0 released in 2016. Google announced official Android support in 2017.

7 Data Types

Int, Double, String, Boolean, List, Map, and nullable types like String?.

var age: Int = 21
var nickname: String? = null

8 Variables

val is read-only (like final); var is mutable. Type inference is the norm.

val pi = 3.14 // read-only

9 Operators

Standard arithmetic/comparison, safe call (?.), the Elvis operator (?:), ranges (..), and is/as for type checks.

10 Control Flow

if/else works as an expression, when replaces switch with pattern matching, plus standard for/while.

val result = if (x > 0) "positive" else "non-positive"

11 Functions

First-class functions with default/named arguments, extension functions, and lambdas.

fun add(a: Int, b: Int) = a + b

12 Classes

class with primary constructors, plus data class for boilerplate-free models.

data class User(val name: String, val age: Int)

13 Objects

The object keyword declares a singleton directly; ordinary instances are created from classes as usual.

14 OOP Concepts

Full OOP support (inheritance, interfaces, polymorphism) combined with functional features like lambdas and higher-order functions.

15 Modules

Code is organized into Gradle modules and packages, with visibility controlled by public/internal/private.

16 Libraries

CoroutinesKtorJetpack ComposeRetrofitExposed

17 APIs

Fully interoperable with Java APIs; Android Jetpack APIs are commonly consumed from Kotlin.

lifecycleScope.launch { fetchData() }

18 Error Handling

try/catch/finally, plus a functional-style Result<T> type for error handling without exceptions.

try { riskyCall() } catch (e: Exception) { println(e.message) }

19 Memory Management

Runs on the JVM — memory is garbage collected automatically, with no manual management required.

20 Performance

Comparable to Java on the JVM. Coroutines provide lightweight concurrency without the overhead of dedicated OS threads.

21 Best Practices

  • Prefer val over var.
  • Use data classes for models.
  • Lean on null-safety instead of platform types.

22 Security

  • Validate all nullable inputs.
  • Avoid force-unwrap (!!) on untrusted data.
  • Use ProGuard/R8 for Android release builds.

23 Accessibility

Jetpack Compose and the Android View system provide contentDescription and accessibility APIs for screen readers.

24 Code Style

Follow the official Kotlin coding conventions: camelCase naming, 4-space indentation, expression-bodied functions where clear.

25 Design Patterns

MVVM

The standard architecture for Android apps built with Kotlin.

Model finite UI/result states exhaustively and safely.

27 Common Mistakes

  • Overusing !! instead of handling nulls properly.
  • Ignoring coroutine scope/cancellation.
  • Mixing mutable and immutable collections carelessly.

28 Interview Questions

Q: What are coroutines?
