CSS

Cascading Style Sheets — the language that gives the web its look. From selectors and the box model to Grid, custom properties, and modern layout, this guide covers CSS end to end.

1 Introduction

CSS (Cascading Style Sheets) is the language that controls how HTML content looks — colors, spacing, layout, typography, and animation. It separates presentation from structure, letting one HTML page be restyled endlessly without touching its markup.

CSS works by applying rules to selected elements. Rules "cascade" — multiple rules can target the same element, and specificity plus source order decide which wins.

  • h1 is the selector — it targets all <h1> elements.
  • color and font-size are properties set inside the declaration block.

    • 2 History

    CSS was proposed by Håkon Wium Lie in 1994 and became a W3C recommendation in December 1996 (CSS1), designed to separate content (HTML) from presentation.

    10 Control Flow

    CSS has no loops, but conditional logic exists through media/feature queries and, increasingly, :has().

    Example 1 — Media query

    @media (max-width: 600px) {
  .nav { display: none; }
}

    Example 2 — :has() parent selector

    .card:has(img) { border: 1px solid pink; }

    11 Functions

    Example 1 — calc()

    12 Classes

    .btn {                     /* class selector */
  padding: 10px 18px;
  border-radius: 8px;
}
.btn.primary {             /* compound class */
  background: deeppink;
}
  • A class starting with . can be reused across many elements.
  • Combining classes (.btn.primary) targets elements with both.

    • 13 Objects

    CSS doesn't have "objects" the way JS does, but the box model is its closest structural concept — every element is a box with content, padding, border, and margin.

    .box {
  padding: 16px;
  border: 2px solid #3a1f5c;
  margin: 8px;
  box-sizing: border-box;
}

    18 Error Handling

    CSS never throws errors — invalid declarations are simply ignored, and the browser falls back to defaults or the next matching rule.

    .box { colour: red; }  /* typo — silently ignored */

    Use browser DevTools to spot crossed-out (invalid) rules.

    19 Memory Management

    CSS itself doesn't manage memory, but inefficient selectors and excessive repaint/reflow triggers (like animating width instead of transform) increase browser rendering cost.

    /* Expensive — triggers layout */
.box { transition: width 0.3s; }
/* Cheaper — GPU-accelerated */
.box { transition: transform 0.3s; }

    20 Performance

    • Prefer transform/opacity for animations (GPU-accelerated).
    • Avoid deeply nested or overly specific selectors.
    • Minify and split CSS by route/component for faster loads.

    21 Best Practices

    • Use a consistent naming convention (BEM, utility-first, etc).
    • Avoid !important — fix specificity instead.
    • Use custom properties for design tokens (colors, spacing).
    • Mobile-first media queries.

    22 Security

    • Untrusted CSS can still be used for UI redress/clickjacking — sanitize user-supplied styles.
    • content: attr() in pseudo-elements can leak data if misused with attribute selectors.
    • Avoid loading stylesheets from untrusted third-party origins.

    23 Accessibility

    • Maintain sufficient color contrast (WCAG AA: 4.5:1 for text).
    • Respect prefers-reduced-motion for animations.
    • Don't rely on color alone to convey meaning.
    @media (prefers-reduced-motion: reduce) {
  * { animation: none !important; }
}

    24 Code Style

    • One property per line, consistent indentation.
    • Group related properties (position, box model, typography, visual).
    • Use lowercase hex colors and shorthand where clear.

    27 Common Mistakes

    • Overusing !important instead of fixing specificity.
    • Forgetting box-sizing: border-box, causing layout surprises.
    • Using pixel values everywhere instead of relative units (rem/%).
    • Not testing responsive breakpoints.

    28 Interview Questions

    Q: What is the CSS box model?
    A: Every element is a box made of content, padding, border, and margin — in that order, from inside out.
    Q: Difference between Flexbox and Grid?
    A: Flexbox is one-dimensional (row or column); Grid is two-dimensional (rows and columns together).
    Q: How does specificity work?
    A: Inline styles > IDs > classes/attributes/pseudo-classes > elements. Higher specificity wins regardless of source order.

    32 FAQ

    Is CSS a programming language?
    No — it's a declarative styling language with no general computation, though it has logic-like features (media queries, calc).
    Flexbox or Grid — which should I learn first?
    Flexbox for simpler one-directional layouts; Grid once you need full 2D control.

    36 Future of the Language

    CSS keeps absorbing what preprocessors used to provide — nesting, variables, and now container queries and scoping — while browser vendors push new layout primitives. It remains the backbone of visual design on the web.
