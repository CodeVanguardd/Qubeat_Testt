7 Data Types

Int, Double, String, Bool, Array, Dictionary, and Optional (Type?) for values that may be absent.

var age: Int = 21
var nickname: String? = nil

8 Variables

let declares a constant, var declares a mutable variable. Type inference is standard.

let pi = 3.14 // constant

9 Operators

Arithmetic, comparison, nil-coalescing (??), ranges (..., ..<), and optional chaining (?.).

10 Control Flow

if/else, a powerful pattern-matching switch, for-in, while, and guard for early exits.

guard let value = optionalValue else { return }

11 Functions

Functions are first-class values, support default and variadic parameters, and closures.

func add(_ a: Int, _ b: Int) -> Int { a + b }

12 Classes

Classes are reference types supporting inheritance, initializers, and deinitializers.

class Animal {
    func speak() { print("...") }
}

13 Objects

Instances of classes or structs. Structs are value types (copied on assignment); classes are reference types (shared) — a core Swift distinction.

14 OOP Concepts

Swift supports classic OOP (inheritance, polymorphism, encapsulation) via classes, plus protocol-oriented programming as an idiomatic alternative.

15 Modules

Code is organized into Swift Package Manager (SPM) packages, exposing APIs via access control keywords: public, internal, private.

17 APIs

The Foundation framework provides core APIs (networking, dates, JSON); URLSession handles network calls.

let (data, _) = try await URLSession.shared.data(from: url)

18 Error Handling

do/try/catch with the Error protocol; throwing functions are marked with throws.

do { try riskyCall() } catch { print(error) }

19 Memory Management

Swift uses Automatic Reference Counting (ARC) instead of a garbage collector — retain cycles must be broken manually with weak/unowned references.

20 Performance

  • Prefer value types (structs) to avoid heap allocation overhead.
  • Avoid unnecessary copies of large collections.
  • Profile with Instruments.

21 Best Practices

  • Prefer structs over classes when reference semantics aren't needed.
  • Use guard for early exits.
  • Lean on Swift's optional safety instead of force-unwrapping.

22 Security

  • Store sensitive data in the Keychain, not UserDefaults.
  • Avoid force-unwrapping (!) on untrusted input.
  • Validate all external data before use.

23 Accessibility

SwiftUI and UIKit provide built-in VoiceOver support via accessibility modifiers like .accessibilityLabel.

24 Code Style

Follow the Swift API Design Guidelines — clear, expressive naming — and use SwiftLint for consistency.

27 Common Mistakes

  • Force-unwrapping optionals carelessly.
  • Retain cycles from strong closures capturing self.
  • Ignoring @MainActor requirements in concurrent code.

32 FAQ

Is Swift only for Apple platforms?
No — it's open source and runs on Linux and Windows too, though tooling is strongest on Apple platforms.

33 Pros and Cons

Pros

  • Fast performance
Cons
